# 相册首次打开短暂显示读取失败：诊断

后续进展：V19 已修复相册等待下载被误报为读取失败的状态展示，详见 [V19 验证](photo-loading-v19-20261004.md)。以下为原诊断记录。

用户补充：开始时出现读取失败，加载后恢复正常。此次只诊断，没有修改产品行为、重配账号或删除缓存。

## 实测

在已连接的华为 DBY-W09 平板、V14 上，使用当前绑定会话执行 GET-only 图片诊断；不输出令牌、图片内容、相册名称或签名 URL。

- 云端可见的四张原图均 HTTP 200。
- 每张在平板上均可解码；现有本机缓存与对应云端原图 SHA-256 一致。
- 原图大小约 6.46、6.82、7.38、10.92 MB，依次读取总耗时 109.622 秒。这是本轮原图诊断耗时，不是 UI 打开耗时，也不能直接等同于服务器带宽实测。
- 诊断测试 `AlbumMediaDiagnosticTest.inspectCloudOriginalsAndDeviceCopies` 通过。

## 原因

`AlbumCloudSync` 先 merge 云端相册元数据，条目即时进入本机数据库；随后逐张下载原图，落盘成功后更新 `importedAtEpochMillis` 触发重新读取。

`IndependentAlbumScreen.AlbumLocalPhoto` 则在元数据出现时立即解码本地路径；文件尚未下载时 decoder 返回 null，组件直接设置 loading=false 并显示“照片无法读取”。下载成功触发重读，所以稍后又正常。

本次证据支持“尚未下载被误判为读取失败”，不支持照片损坏、配对失败或 OSS 权限拒绝。大原图顺序下载延长了这一错误提示可见的时间。

## 后续修复方向（本轮未实施）

把等待下载、下载失败、文件已存在但无法解码分开；等待时展示中性占位，不显示失败。优先下载当前可见照片的缩略图，原图按查看/保存需求下载并缓存。不能只把所有错误统一改成加载中，否则真实损坏会永远等待。
