# 月笺指导图一致性与功能完整化规格

日期：2026-10-01  
状态：待用户审核，审核通过后进入执行计划  
适用端：Android 首发；服务端接口保持 iOS 后续兼容

## 1. 目标与决策

本规格由用户最新确认的要求驱动：六张指导图不再只是气氛参考，而是页面结构、信息层级、图标语义、间距比例、内容呈现和状态反馈的强约束。实现必须以真实 Room 数据驱动，不得用演示列表、静态截图或整张指导图作为页面背景。

本轮目标不是再做一个 UI 骨架，而是让以下路径可实际使用：

`打开应用 → 浏览时间轴 → 新建个人/共同记录 → 保存/发布 → 打开详情 → 评论/追加视角 → 相册查看媒体 → 城市记录故事 → 使用时间功能 → 选择性导出`

当前实现中 `FutureFeatureScreens.kt` 仍是相册和地图占位页，服务端媒体校验只接受图片；因此“页面做出来”与“功能可用”必须拆成 UI、数据、同步、设备验收四个条件，缺一不能标记完成。

### 2.1 强制视觉规则

- 390×844 是第一轮对照尺寸；其他 Android 尺寸必须通过布局重排，不得把 390 的坐标硬编码成固定画布。
- 指导图的结构必须逐项出现：封面、时间轴、缝线、作者身份、具体时间、媒体卡片、底部导航不可被“简化成几张圆角卡片”。
- 图标使用统一细线描边体系；底栏的图标必须与“时光/相册/记录/地图/我们”语义一致，不使用与标签无关的图片、音符或通用替代图标。
- 默认暖米色，纯白为可切换主题；主题只改变颜色和纸张表面，不改变信息结构。
- 中文正文最小 14sp，触控目标最小 48dp；键盘弹出时完成/发布入口必须可见。
- 真实数据为空时保留指导图的层级和装饰，但明确写空态，不填充虚构记录、点赞、统计或媒体。
- 任何与指导图的结构、图标、颜色、间距或层级偏差，都必须在视觉复核记录中列出；不得以“差不多”验收。

## 3. 页面与功能规格

### 3.1 时光首页

数据源只能是 Room 的已发布记录和本机未同步记录。页面从上到下为：

1. 可替换封面、纪念日副文案和换图入口；
2. 当前日期标题与纸面分隔；
3. 左侧贯穿全页的缝线和作者节点；
4. 按自然日分组的记录；每条显示头像、名字、具体时间、标题/正文预览、媒体摘要、评论入口和同步状态；
5. 图片、视频、音乐和城市故事以不同内容卡呈现，不伪装成普通文字条；
6. 固定底部五栏：`时光 / 相册 / ＋记录 / 地图 / 我们`。

整条记录可点击进入详情，点击图片/视频进入媒体查看，点击评论进入详情评论区。首页必须一滑到底，不按天分页。

### 3.2 个人记录

- 点击 `＋记录` 直接进入正文，不先选择媒介、不设置必填字段。
- 标题可选，正文自动保存到本机草稿。
- 发生时间可查看和修改，保存故事发生时区。
- 媒体工具栏支持图片、视频、语音、音乐链接、城市快照和更多入口；未接通的能力显示禁用原因，不显示无效按钮。
- 页面状态区分：`草稿已保存`、`等待同步`、`已同步`、`同步失败，点击重试`。
- 发布后作者可编辑自己的记录、查看版本、删除并在冷静期内恢复；对方只能查看和评论。

### 3.3 共同记录

共同记录不是聊天气泡，也不是普通记录加“共同”标签。它由一个主题和两个独立作者块组成：

- A 创建主题并写自己的视角；
- B 打开同一主题，追加自己的视角；
- 每个作者只能编辑自己的块，对方块只读；
- 每次发布修改追加版本快照，详情页可以查看版本时间、作者和恢复入口；
- 评论独立于视角正文，不混入作者块；
- 时间轴显示主题、双方名字、每个视角的具体时间和同步状态。

### 3.4 详情页与评论

- 首页卡片和媒体入口必须打开同一条详情；
- 详情页完整渲染标题、正文、媒体、城市信息、共同视角和版本；
- 评论区显示作者和具体时间，支持发送、失败重试和本地离线排队；
- 记录未同步时仍能读取本机完整内容，并明确提示对端尚不可见。

### 3.5 共同相册

- 默认按月份分组展示所有已发布图片和视频；
- 图片支持大图浏览、来源记录、作者和发生时间；
- 视频显示封面、时长和播放控制；播放失败保留重试；
- 相册集只是媒体引用集合，不复制原始媒体；删除相册集不删除原记录；
- 空态必须是可理解的“照片会出现在这里”，不能伪造演示图片；
- 媒体详情可以回到原记录，保证相册不是孤立文件夹。

### 3.6 城市地图与故事

- 只有用户主动点击“记录地点”才请求一次位置；不做实时定位、后台定位或轨迹；
- 默认保存城市级名称；精确坐标只作为主动快照的附属数据，页面默认不展示精确住址；
- 无权限时支持手动选择城市；
- 地图页展示城市卡片/地图聚合和城市故事列表；点击城市进入该城市的记录；
- 城市故事可以来自新建记录，也可以关联已有记录；
- 地图不可达时城市列表仍可用，不能让整个页面变成错误页。

### 3.7 我们页与资料

- 双方头像、名字、身份色和封面均可在应用内修改；
- 暖米色/纯白主题为本机偏好，不覆盖对方；
- 中秋作为纪念日语义呈现，不做整套节日皮肤；
- 纪念日与倒计时、时间胶囊、数据导出、通知设置进入真实可操作页面；
- 资料保存失败时保留输入，不静默回退。

### 3.8 时间与回看功能

- 纪念日：日期、名称、是否每年重复、倒计时展示；
- 时间胶囊：正文和媒体发布后，在指定日期前显示锁定状态，到点才可打开；
- 过去的今天：按月日查找早年的已发布记录，不复制原数据；
- 本周小结：确定性组合本周文字、照片、音乐和城市，不调用 AI，不评分；
- 每周回看：固定时间呈现一条明显更早的真实记录，可关闭；
- 新记录提醒：只提示对方有新记录，不在通知中携带正文或媒体地址。

### 3.9 导出

- 支持按记录或时间范围选择性导出；
- 导出结构化 JSON、可读 Markdown 和被引用的原始媒体；
- 共同记录必须保留作者、版本和时间；
- 导出产物脱离服务端仍可阅读；
- 导出过程显示进度、失败原因和重试入口，不阻塞正常记录。

## 4. 数据与接口增量

现有 `BlockType` 已预留 `VIDEO/AUDIO/MUSIC/LOCATION`，但当前服务端媒体校验只允许 `IMAGE`。实现必须按以下契约扩展，不能只在 UI 中增加按钮：

| 领域 | 新增/调整 | 关键约束 |
| --- | --- | --- |
| 媒体 | `media_asset.kind = IMAGE/VIDEO/AUDIO`，上传、处理、下载状态 | 服务端校验 MIME、大小、尺寸/时长和校验和；`READY` 前不可发布 |
| 音乐 | `music_link` 或 MUSIC block | 接收系统分享的网易云链接、标题、封面和分享文本；不依赖网页抓取，不保存用户凭据 |
| 城市 | `location_snapshot` | 城市名、可选经纬度、发生时间、关联记录；无后台定位和轨迹 |
| 相册 | `album`、`album_item`（引用 media/entry） | 删除相册不删除原记录和媒体 |
| 纪念日 | `anniversary` | 名称、日期、是否重复、所属空间 |
| 时间胶囊 | `time_capsule` 或 entry 的锁定元数据 | 开启时间前服务端和客户端均不得返回正文 |
| 回看 | 查询/本地派生结果 | 不复制源记录，不引入统计和 AI 内容 |
| 导出 | 版本化导出 DTO/任务 | 不含 token、配对密钥和长期下载 URL |

所有新增实体都必须带 `couple_id`，由认证会话确定归属；客户端不能凭 UUID 越权读取。变更写入、同步游标和 Room 读取模型必须遵循现有数据规范。

## 5. 执行阶段与交接边界

### V0：基线与状态契约

- 给 APK 增加可见的版本/短 SHA；
- 固定设计 token、五栏导航图标接口、作者身份色和页面状态枚举；
- 为每个页面建立真实数据/空态/错误态/离线态；
- 不新增演示数据。

### V1：核心记录闭环

- 首页、个人编辑、共同编辑、详情和评论；
- 自动保存、发布状态、失败重试、版本入口；
- 目标是两台设备完成“写入—打开—同步—评论”。

### V2：媒体与共同相册

- 图片体验按指导图重做；
- 服务端/客户端扩展视频和音频；
- 相册月分组、媒体详情、视频播放和失败恢复。

### V3：城市地图

- 一次位置快照、城市选择、城市故事关联；
- 地图/城市列表降级策略；
- 城市页与时间轴、详情页互相跳转。

### V4：时间与音乐

- 网易云分享接入；
- 纪念日、倒计时、时间胶囊；
- 过去的今天、本周小结、每周回看和提醒。

### V5：导出、恢复与完整视觉验收

- 选择性导出和媒体打包；
- 真实数据恢复、导出内容抽样；
- 六个页面在目标设备逐屏对照指导图。

### V6：双机发布验收

每个阶段都需要对应 APK/commit、设备型号和真实操作证据。V6 只有在以下条件同时满足时才可标记完成：

1. 所有页面不再是占位页；
2. 首页、编辑器、详情、相册、地图和我们页都能从真实数据完成主路径；
3. 至少一台真实 Android 手机完成安装、记录、同步、媒体、地图快照和导出；
4. 另一端能看到允许共享的内容，越权和离线状态有明确反馈；
5. 指导图逐屏复核无未解释的结构性偏差；
6. 不以构建成功、单元测试或静态截图替代真实使用证据。

## 6. 双机文件边界

- 本机：`android/feature/*`、`android/core/designsystem`、Compose 导航、页面状态和视觉验收文档。
- 另一台机器：`server`、`android/core/database`、`android/core/network`、`android/core/sync`、媒体/地图/导出接口、迁移和真机构建测试。
- `android/app/src/main/java/com/twomemory/app/AppNavigation.kt` 与 `SyncSession.kt` 是接线文件；任何一方修改前必须先在交接文档写明接口，不得同时编辑。
- 每阶段独立 commit，提交说明包含阶段号；没有 APK commit、设备证据和已知缺陷清单，不得称为“完成”。

## 7. 明确不做

- 实时定位、后台持续定位和行动轨迹；
- 多人空间、公开社交、复杂账号中心；
- AI 代写、AI 总结、关系评分、记录数量/活跃统计；
- 用整张指导图做背景或用硬编码演示记录伪造功能；
- 为了追求像素相似而牺牲真实数据、离线可读性和导出能力。
