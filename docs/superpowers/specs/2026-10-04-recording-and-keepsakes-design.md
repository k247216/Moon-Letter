# 记录与纪念品：用户已授权直接实施

## 目标
以记录、互相观看和保存为核心，不做打卡、成就或累计统计。用户已确认未读、快速记录、语音资产、纪念册导出、可暂时不分享和历史草稿方向，并要求直接执行，不再逐项询问。

## 本轮交付边界
1. 本人阅读状态：已发布的伴侣记录显示“新回忆”，打开详情后标为已看；可跳至下一篇未看。记录 ID 逐条保存，补写旧日期也应被识别为新记录。阅读状态仅本机、按账号/服务空间隔离，不是对方可见的已读回执。
2. 首页“记下今天”直接进入新记录，标题可不填；已有草稿先保留到草稿箱。日常新建与继续草稿分开，避免每次误进旧内容。
3. 草稿箱保存多篇完整未完成内容：文字、图片、录音/视频附件、地点、发生时间。编辑自动持久化，强退后可继续；发布成功只删除对应草稿，失败保留。草稿本轮明确仅本机、暂不分享，不声称云端私密记录已完成。
4. 纪念册先交付离线 HTML+媒体 ZIP，纸张/日期章节/照片/回应排版，音视频可播放。JSON/Markdown保留备份用途；原始文件缺失要报告，不能静默出空相片。只包含当前本机可读取的已发布记录，不混入草稿或锁定时间胶囊。PDF打印版作为后续独立打磨。
5. 云端图片/音频/视频继续现有上传下载链路；本轮核验而不新建无权限保护的存储接口。云端长期私密发布/转公开需要服务端 ACL 改造，另阶段实施，不以隐藏 UI 代替。
6. 地图去掉累计摘要数字，保留城市故事卡的数量/日期作为查找信息，不做统计页。

## 安全和兼容
不卸载、不清配对、记录或原始媒体；不重置数据库；不提交/推送包含先前工作的脏工作树。当前用户持续要求在现有项目直接推进，本轮原地工作并保留全部既有改动。
草稿删除只移除用户明确删除的草稿元数据，不删除可能被其他记录引用的媒体原文件。
未知/不可读媒体不加载外部脚本；导出转义文字、使用打包相对媒体路径，不写令牌、签名 URL 或本机路径。

## 验收
真实持久化测试、多草稿隔离、失败保存、未读旧日期/重启/空间切换、HTML注入转义、ZIP原媒体字节验证、导出不包含草稿；手机与平板尺寸 UI 操作检查；交付签名 APK 和真实未完成项。
