# 月笺：记录体验闭环与分类云端化

日期：2026-10-03。依据用户对 v8 的逐项反馈。本文件是下一轮重构的设计与验收边界，不代表代码已经实现或云服务已经上线。沿用用户自主推进要求；不自动采购、登录云账号、部署、提交或推送。不改动已有数据归属。

## 目标与实施顺序

目标不是继续增加入口，而是让两个人能真实写、补写、回应、录音、收藏照片、按城市回看，并在云端连通后跨设备读取与下载。

先完成首页/详情/编辑器/城市故事的共同视觉语言与真实本机链路，再推进分类同步、服务端接口和部署。通知、时间胶囊、共同记录必须分别验收，不能用 UI 测试通过代替双机完成。

备选路线：只修样式成本低但保留假功能；先部署云服务会把不完整模型搬到线上；推荐先修记录体验和数据语义，再接分类云端。三个里程碑：A 记录视觉与发布语义；B 音乐分享、录音、共同补写及提醒闭环；C 分类云端与真实双机验收。每一批交付独立版本/指纹，不将文档更新冒充新 APK。

## 已核查的现状

- AppNavigation 的外层 Scaffold 把窗口安全区 padding 应用于所有页，首页封面尚未采用完整沉浸式状态栏方案。当前截图夹具不包含整个宿主窗口，状态栏问题依据代码与用户反馈，不能算已做全窗口视觉复现。
- 首页 v8 默认封面约 32%，文字/图片位置和回复入口仍产生较大纵向留白；城市故事使用另一套简单正文布局，未复用首页内容卡。
- EntryDetailScreen 仍是头部 Surface、逐个块纵排、简单回应列表；音乐展示裸链接，音频存在未接通占位文案。
- EntryDetailViewModel 只用 entry.state 映射 DRAFT。SyncSession.publish 已调用 LocalEntryWriter.save(publish=true) 写本机与队列，再触发同步。因此数据库 DRAFT 不能直接判定为用户主动保留的私密草稿。
- EditorPhotos 的语音按钮为 audio/* GetContent 文件选择，不是录音。
- SharedEditorRoute 只是 PersonalEditorScreen 包装；EditorUiState 有 partnerName/partnerBody，但入口没有完整加载及伴侣针对同一 entryId 补写的链路。
- ShareReceiverActivity 已接收普通文字/图片分享，但不会把音乐软件文本链接转换为歌曲块。
- 纪念日已有服务端保存/读取；通知只有每周回看和同步后新记录通知。没有查到纪念日/倒计时专用调度。
- 胶囊是本机 SharedPreferences 明文，按本机日期显示；服务端没有胶囊接口，不是云端封存。
- 独立相册本机 Room/私有文件已有；服务端 V1 已有 album、album_item 表，但未查到对应 Java API，不应重复建表或宣称已经同步。
- 保存到手机是 API 29+ MediaStore Pictures/MoonLetter 原字节副本；API 26–28 使用系统文档保存。它不是上传到云端。

## A：同一本手账的首页、详情和城市故事

### 首页

- 封面背景延伸到状态栏后方，不新增一条纯色状态栏；文字、按钮仍避让刘海/系统图标，滚动时正确改变图标明暗。
- 普通字体先以可视高度约 22–25% 为试作目标，首屏应露出第二条记录开头；最终以同尺寸截图与真实内容检验，不用硬比例挤坏大字体。
- 引言字号小于日记正文主标题，保留简短纪念日提示（真实事件才显示），封面不承担多段正文。
- 日章节、作者/时间、轻微纸张边界/缝线节点和回应行构成一条明确记录。避免厚重统一圆角卡，但不能让不同记录连成无区分的大段正文。
- 文图同组布局：短文与拍立得并排，长文自然流到图片下方；多图采用可点开的小拼贴，图下可承接说明。紧凑/窄屏/大字体自动改上下布局。无固定大空白或强迫每条卡同高。
- 回复数量来自真实数据；不生成装饰性点赞人数或不存在的记忆。

### 详情

- 真正的回忆页：日期章节、作者/真实头像、标题、城市标签、正文与照片排版、音乐/录音专用组件、双方视角、回应区。
- 图片可放大与翻页；后续与媒体通用下载能力连接，不能仅靠详情截图展示。
- 回应是正文之后的轻量对话，显示作者、时间与内容，底部写回应输入。输入不因同步刷新丢失；本机持久保存与对端可见分开验收。
- 待同步发布记录不出现“永远只在本机”提示，也不显示已同步/对方已读假状态。真实私密草稿仅在草稿语境提示“尚未发布”；不直接给草稿开放服务端回应。
- 判定须结合发布意图/待执行操作，而不是 DRAFT 字段。旧数据无足够证据时不得自动发布、上传或改变隐私。

### 城市故事

- 保留真实地图、搜索与点选；继续打磨图钉、标题、来源、缩放后的标签密度，不凭空画道路冒充真实数据。
- 下半部分直接复用手账记录组件和媒体数据：日期章节、头像/时间、文图关系、录音/音乐、回应入口及同一详情页。
- 显示真实记录数、首次出现日期；空城市使用简短写故事入口，不制造故事或用虚假内容填空。

## B：编辑器与真实内容

### 工具和地点

依 personal-entry-editor.png / shared-entry-editor.png 保留六项等宽工具：图片、视频、语音、音乐、城市、更多。图标统一线条/尺寸，点击区域至少 48dp；“更多”提供已有真实能力，不再弹空功能说明。

工具栏上方独立显示地点（可修改/移除）、时间胶囊设置（未接完整链路前不伪装已封存）、存为草稿。发布与草稿是不同明确操作。图片/正文/媒体按内容块显示并持久保存顺序，而不是所有附件都丢在文章末尾。

### 共同记录

不是共享光标的实时文档，而是“同一篇回忆，两个人各自补写”。创建者发布后，伴侣从同一条详情进入“补写我的视角”，携带 entryId；双方内容按块归属/顺序展示，每人编辑自己的块，另一个人的内容只读。

服务端需要检查同空间、记录模式、块所有权、操作幂等和版本冲突；离线补写仍写本机队列，联网不重复、不覆盖伴侣的块。不靠 partnerBody 假文案模拟对方已参与。验证 A 发布→B 补写文字/录音→A 看到→两端重启保留。

### 音乐

采用系统分享接入，而不是要求用户填三个字段。网易云/QQ 音乐等应用提供文本分享时，月笺识别受支持链接与现有文本中的歌名/歌手，保留来源及原始链接；用户确认后加入歌曲块。已有手动入口保留为兜底，允许只有名称/歌手的小标签。

点击歌曲卡使用系统处理该合法链接的应用，安装了原应用时尝试回到歌曲页面；没有应用时打开网页。不能保证所有音乐应用的每一种短链接已兼容，须分别真机验收。只接受安全 URL，拒绝 javascript/file 等方案；不在 WebView 执行任意分享内容，不偷偷爬取绕过授权。

未获得授权的音乐音源不下载到 OSS；不承诺内嵌完整版权播放。封面无法可靠获取时使用统一唱片组件，不盗用无来源封面。

### 录音

“语音”打开录音面板：首次请求麦克风权限→开始→显示真实时长/采样振幅→停止→试听→确认加入/重录/取消。文件导入放到更多，不能代替录音。

AAC/M4A 原件存 App 私有持久目录，记录时长、MIME、文件大小及可用校验。停止过早/无有效音频不得加入；权限拒绝、取消、来电/后台中断须释放麦克风并正确处理自己的临时文件。未经用户启动不后台录音。

正文/详情/时间轴均可播放且显示时长；音频经后续媒体上传门禁变成 READY 才向伴侣发布关联，不把空路径伪装成功。真机验收听到实际录制内容，模拟器按钮测试不能替代录音质量。

## 提醒与胶囊

- 纪念日/倒计时先补事件列表、下一次日期与实际提醒配置，设置完能看到“提醒时间/通知权限”而非只有已保存文案。
- 设置页提供明确由用户触发的“发送测试通知”和系统通知设置入口；测试注明这是本机通道检查，不是伴侣通知或业务提醒验收。
- 验收需覆盖前台、后台、锁屏、重启、通知拒绝、改时间、删除事件和重复去重。WorkManager 不承诺精确到分钟；国内后台推送路线不能把 FCM 当已验证方案。
- 胶囊服务端保存开启时间/时区/参与权限，开启前同步封面与时间元数据、不下发正文或媒体读取权限，以服务端时间判断解锁，不能改手机时钟绕过。
- 提供测试环境的短时胶囊，在真正到期前不能看，到期后双方能打开；不将未开启正文混入普通导出/缓存。服务器可访问正文不等于端到端加密，不能用营销文案混淆。

## C：分类私有云端

沿用已确认阿里云 ECS + PostgreSQL + 私有 OSS 路线。PostgreSQL 保存分类和关系，OSS 保存原始图片/视频/录音/头像；两者都需要备份，单独备份数据库不是完整恢复。

业务分类：记录/内容块/回应、独立相册/照片/分类/封面、城市关联、纪念日/倒计时、胶囊、成员资料与头像。分类通过数据库模型管理，不靠 OSS 文件夹名冒充权限。媒体以稳定 assetId 关联，城市只引用记录，不复制一份媒体；相册仍独立于记录。

每个实体写操作需要明确进入同步变更流；服务端基于 coupleId 和成员身份校验上传、读取、更新、下载权限。移动端仅持有短时授权，不持有数据库口令或 OSS 长期密钥。

媒体闭环：本机持久原件→后台上传/完成确认→服务端实际验证对象→READY→发布关联→B 端授权读取→按需下载到系统相册/文件。客户端上传的 SHA 元数据不能单独证明真实文件 SHA；按存储提供的校验能力或服务端实际计算验证。重试幂等，失败不误删源文件；删除需同步墓碑，并区分云端删除与清理本机缓存。

两端 Room 是离线缓存和队列，OSS 私有对象是上传成功后的云端原件；“保存到手机”是用户主动创建的系统可见副本，与缓存和云原件不同。

相册默认相册集（封面、名称、分类、张数、最近更新），页内“相册/全部照片”切换，记住用户选择。相册内照片按月份展示；云端补单张和整册下载，整册操作可取消/失败重试。云端分类只同步用户确认加入的相册照片，不扫描整台手机自动上传。

## 导出的定位

上云后仍保留，但放入“数据与备份”的次级入口：数据可迁移/用户不被锁定、离线归档、选择性分享。现有 Markdown/JSON 是记录文本与结构导出，不是云备份，也不是完整含媒体档案。

之后实现清单+JSON+人可读文档+原媒体 ZIP，并附版本/时间/校验，处理失败清单；另行验证导入恢复。分享默认选中条目/时间段，不顺带公开整个空间；封存胶囊不导出。音乐只导出元数据/原分享链接，不打包版权音源。

## 验收与未授权边界

- 本轮仅核查代码与重新采集 v8 视觉夹具，产品改动尚未实现；原包仍 v8。
- A 批需全窗口状态栏截图、同内容前后对照、紧凑/大字体/键盘、图片详情和草稿/待同步区分测试。
- B 批需真机录音试听、音乐 App 分享与回跳、共同 entryId 双机补写、实际通知及胶囊到期证据。
- C 批需真实云地址上 A 写→B 读/回应→A 看，独立相册跨设备/下载、音频/头像、断网重试、第三方越权拒绝与新设备恢复。
- 云账号、资源采购、生产部署、域名/证书、地图商用授权和国内后台推送选型需专门沟通；不在本次核查中擅自执行。
