状态：**已确认手机截图呈现的是旧界面；核心 UI 壳层已推进到 `926ebdb`，但当前代码的手机可用性仍未验证，不能宣称修复。** 首次排查基线提交 `966f5b6`，当前交接提交 `926ebdb`，分支 `m1-stable-recording-loop`。本文件是执行交接，不改变已批准的 [M1 规格](../superpowers/specs/2026-10-01-self-use-m1-design.md) 和六张 [指导图](../design/reference/)。

## 1. 用户现场反馈与代码事实

用户实测：界面几乎是纯色，图标不符；首页像聊天短条而不是指导图的连续手帐时间轴；点不开/看不全记录；「发布」「保存」反馈不清。**这些是现场问题，不得被单元测试绿灯覆盖。**

### 1.1 2026-10-01 用户手机截图定位

用户提供了三张 1080×2400 首页截图；SHA-256 完全相同，实际上只覆盖**同一个首页状态**，没有编辑器、详情页或点击后的画面。截图包含「我们的时光」「中秋 · 仍在一起写着」、两张细边框圆角文字卡，以及底栏的图片/相机/加号/定位/音符图标。它们逐项对应 `git show d44c832^:android/feature/timeline/src/main/java/com/twomemory/timeline/TimelineScreen.kt` 和同版本的 `BottomNavigation.kt`；`d44c832` 于 2026-10-01 13:00 已替换该首页实现。旧 `TimelineCard` 没有点击回调，故旧包上「点不开」不是用户操作问题。

**结论边界**：截图证明手机运行的视觉版本早于上述改造，不能从截图确定 APK 的精确 commit，也不能证明当前 HEAD 的详情页在真机可用。`app/build.gradle.kts` 仍写 `versionCode=1`、`versionName=0.1.0`，光看系统应用信息无法区分新旧 APK。P0-A 首步须让 APK 可见短 SHA（当前仅在「我们」页显示 M1/版本证据，SDK 机器仍需确认 APK 对应 SHA），并在测试设备先演练旧包升级保数据，再让用户覆盖安装并按同一条真实记录复测；不要先改 Room 或让用户清除应用数据。

### 1.2 单屏审查（仅限这张首页）

1. **首屏，不通过**：指导图是可换月色封面接连续纸面时间轴；实机是浅色整页、无封面，前两条记录占用不到半屏，剩余大块空白。当前代码虽已加入封面和日期分组，仍需新版 APK 实机截图才能判断改进幅度。
2. **记录入口，不通过（旧包）**：两条重复日期、作者「我」与正文 `hh` 的卡片没有详情提示；旧源码也确实无点击回调。下一包必须在原有记录上验证整卡点击、全文、返回，再谈视觉细节。
3. **底部导航，不通过（旧包）**：「时光」却用图片符号、「我们」用音符，语义与指导图不符。当前代码换成通用 Material 图标，语义较正，但造型仍需专用图标和真机对照。
4. **可读性风险，待实机核对**：白色状态栏文字/图标压在浅米色顶部，截图中对比度很低；必须给浅色页配置深色状态栏图标或让顶部改为足够深的封面。单张截图不能判断屏幕阅读器、焦点与动态字体表现。

## 3. 按用户路径重新排序（P0 不通过，不扩功能）

### P0-A：确认安装物与首条文字闭环（另一台开发机，SDK/服务端所有者）

1. 用同一 commit 构建 APK，在应用内显示版本/短 SHA；先在测试设备上从截图所示旧包升级，验证 Room 数据仍在且能打开，再让用户手机覆盖安装，记录 `debug/release`。`versionName=0.1.0` 不能辨别旧包。**保留现有应用数据**，除非已完成备份且单独取得清数据授权；不能用“仓库已更新”代替重新安装。
2. 检查服务器地址、同一 Wi-Fi/网络、会话、配对；首位成员和第二位成员都走一次。release 无默认服务器地址是刻意设计，安装说明必须给出实际可达地址；不要把开发机 IP 写死回代码。
3. 在 A 机创建一条仅文字记录：检查 Room `entry/entry_block/outbox`、首页条目和详情页全文；A 机点击卡片应立即打开，离线也能读本地内容。
4. B 机前台拉取后能看到该条全文和作者、具体时间；B 评论后 A 可见。切断网络再发一条、恢复网络，验证状态由待同步变为已同步且不重复。
5. 若用户的“点不开”在新版仍复现，保存设备录屏、Logcat、entry ID、当前页面与相关异常，不先猜是手势或排版问题。旧 APK 的卡片无点击入口已从源码确认；记录新旧画面差异，但旧 APK 的精确 SHA 无法从现有截图倒推。

退出条件：以上双端路径在目标设备有记录和证据，且无数据丢失；否则不得将 M1 评为可用。执行证据写回 `m1-acceptance.md`，真实使用日志另建 `docs/testing/real-use-log.md`。

### P0-B：让首页与编辑/详情页回到批准的产品形态（本机，视觉与交互所有者）

1. 以 `home-timeline.png`、`personal-entry-editor.png`、`shared-entry-editor.png` 为唯一视觉方向，先做 390×844 目标机截图对照；界面包含暖米色/纯白主题选择，但不是整页纯色。纸张纹理、分组日期、左侧缝线、头像、具体时间、照片呈现、底栏尺寸与图标须逐项核对。
2. 先修首页首屏、真实条目、空态、详情全屏，再修个人/共同编辑器。点整条记录应打开详情；长文、图片、两名作者、键盘弹出、200% 字体都不能遮挡关键操作。
3. 文案明确区分「留在本机的草稿」「已存本机，等待同步」「已同步，可被 TA 看见」；失败保留内容并显示重试入口。视觉层只消费明确状态，不用含糊的 `saved` 推断对端已收到。
4. 使用批准图中的头像/封面资源与同一风格的专用图标；默认图和用户换图路径都要验。不得用截取整张指导图伪造业务内容，不得增加虚构点赞/统计。

退出条件：同一设备尺寸下的实机截图和指导图逐屏并排复核，记录差异与修正；用户能在首页找到、点开、读完刚写的真实条目。收到目标机截图前可以按指导图推进代码，但**不得宣称视觉一致或手机问题已修复**。

### P0-B 当前代码交接（`926ebdb`）

- 首页默认不再展示演示封面：标题「我们的时光」和「中秋 · 仍在一起写着」位于暖米色顶部；用户主动选择背景图后才显示封面。
- 每张纸卡显示日期、具体时间、作者/头像、共同标记、正文和媒体预览；整张卡是详情入口，详情仍由 Room 数据驱动。
- 底栏五个入口统一为「时光 / 相册 / ＋记录 / 地图 / 我们」，不再把「＋记录」绘制成抢占层级的悬浮圆按钮。
- 「我们」页显示头像、名字编辑、主题选择、配对/通知区和 `M1 · versionName` 证据；纪念日、时间胶囊、导出等未接通入口明确写「还没开放」。
- 本机静态验证：`git diff --check` 通过；未运行 Gradle/SDK/模拟器。下一台机器必须先构建、安装、截图，再决定还需哪些视觉修正。

### P1：补齐“共同记录”真实语义（双机按边界协作）

- 另一台开发机负责数据/API/同步：同一主题下两人的作者块独立追加、只可改自己的块、修改形成版本快照、跨端拉取后的顺序与身份稳定；要给 UI 一份明确状态契约。
- 本机负责 UI：详情页给第二位成员「写下我的视角」入口，两个作者的块、具体时间和版本入口清楚分隔；不能显示成普通聊天气泡。评论在记录之外，不能混同视角正文。
- 验收：A 建共同主题，B 从详情追加视角，A/B 各修改自己的块，双方看到作者和版本，越权编辑被阻止；每一步在两台设备有证据。

### P2：真实使用后扩围

系统分享入口、长期稳定同步与备份/导出仍是 **M1 必须完成**，排在 P0 和 P1 的真实闭环之后验收，不得顺延成 M2。M1 首条真实闭环通过后，再依次推进共同相册与视频/语音、城市故事、纪念日/倒计时、时间胶囊、过去的今天及非 AI 周小结。M1 占位页不可当作已交付能力。

## 4. 协作防冲突规则

- 另一台机器只改 SDK、服务端、Room/同步及其测试；本机只改 Compose 页面、设计系统资源和视觉验收文档。`AppNavigation.kt`、`SyncSession.kt` 是交界文件，改动前先在本文件记录接口约定并由一方一次性接线，不在两台机器上同时改。
- 每个任务提交独立 commit；提交信息含任务号，报告改了什么、未验证什么、APK SHA。仓库分支推进不等于用户手机更新。
- 真机证据回填验收表后再勾执行计划；任何 UI 对照必须用**真实 Room 数据**。构建与设备测试留在 SDK 机器，本机不启动 Gradle/模拟器。
