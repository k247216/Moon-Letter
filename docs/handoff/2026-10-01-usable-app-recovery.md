## 1. 用户现场反馈与代码事实

用户实测：界面几乎是纯色，图标不符；首页像聊天短条而不是指导图的连续手帐时间轴；点不开/看不全记录；「发布」「保存」反馈不清。**这些是现场问题，不得被单元测试绿灯覆盖。**

| 反馈 | 当前代码证据 | 结论与下一步 |
| --- | --- | --- |

## 2. 停止用“构建成功”替代“能用”

当前验收台账 `docs/testing/m1-acceptance.md` 仍为 `NOT VERIFIED`：S/A 为开发机证据，E1/H4 只有部分证据，E2、设备数据恢复、U 类视觉与真实使用未通过。最新提交虽补了恢复、图片、评论、通知等链路，但**没有一次用户手机上的「打开→写一句→明确保存状态→点开看完整内容→另一端看见」完整录像**。`real-use-log.md` 仍不存在。后续每次交付都要附：APK 对应 commit、设备型号/Android 版本、服务端地址是否可达、两端操作录像或逐步截图、问题复现步骤；无这些材料只写「代码完成/待设备验收」。

## 3. 按用户路径重新排序（P0 不通过，不扩功能）

### P0-A：确认安装物与首条文字闭环（另一台开发机，SDK/服务端所有者）

1. 用同一 commit 构建 APK，显示版本/短 SHA，确认用户手机安装的确是该 APK；记录 `debug/release`。不能用“仓库已更新”代替重新安装。
2. 检查服务器地址、同一 Wi-Fi/网络、会话、配对；首位成员和第二位成员都走一次。release 无默认服务器地址是刻意设计，安装说明必须给出实际可达地址；不要把开发机 IP 写死回代码。
3. 在 A 机创建一条仅文字记录：检查 Room `entry/entry_block/outbox`、首页条目和详情页全文；A 机点击卡片应立即打开，离线也能读本地内容。
4. B 机前台拉取后能看到该条全文和作者、具体时间；B 评论后 A 可见。切断网络再发一条、恢复网络，验证状态由待同步变为已同步且不重复。
5. 若用户的“点不开”复现，保存设备录屏、Logcat、entry ID、当前页面与相关异常，不先猜是手势或排版问题。若旧 APK 才复现，记录旧/新 SHA 与差异。

退出条件：以上双端路径在目标设备有记录和证据，且无数据丢失；否则不得将 M1 评为可用。执行证据写回 `m1-acceptance.md`，真实使用日志另建 `docs/testing/real-use-log.md`。

### P0-B：让首页与编辑/详情页回到批准的产品形态（本机，视觉与交互所有者）

1. 以 `home-timeline.png`、`personal-entry-editor.png`、`shared-entry-editor.png` 为唯一视觉方向，先做 390×844 目标机截图对照；界面包含暖米色/纯白主题选择，但不是整页纯色。纸张纹理、分组日期、左侧缝线、头像、具体时间、照片呈现、底栏尺寸与图标须逐项核对。
2. 先修首页首屏、真实条目、空态、详情全屏，再修个人/共同编辑器。点整条记录应打开详情；长文、图片、两名作者、键盘弹出、200% 字体都不能遮挡关键操作。
3. 文案明确区分「留在本机的草稿」「已存本机，等待同步」「已同步，可被 TA 看见」；失败保留内容并显示重试入口。视觉层只消费明确状态，不用含糊的 `saved` 推断对端已收到。
4. 使用批准图中的头像/封面资源与同一风格的专用图标；默认图和用户换图路径都要验。不得用截取整张指导图伪造业务内容，不得增加虚构点赞/统计。

退出条件：同一设备尺寸下的实机截图和指导图逐屏并排复核，记录差异与修正；用户能在首页找到、点开、读完刚写的真实条目。收到目标机截图前可以按指导图推进代码，但**不得宣称视觉一致或手机问题已修复**。

### P1：补齐“共同记录”真实语义（双机按边界协作）

- 另一台开发机负责数据/API/同步：同一主题下两人的作者块独立追加、只可改自己的块、修改形成版本快照、跨端拉取后的顺序与身份稳定；要给 UI 一份明确状态契约。
- 本机负责 UI：详情页给第二位成员「写下我的视角」入口，两个作者的块、具体时间和版本入口清楚分隔；不能显示成普通聊天气泡。评论在记录之外，不能混同视角正文。
- 验收：A 建共同主题，B 从详情追加视角，A/B 各修改自己的块，双方看到作者和版本，越权编辑被阻止；每一步在两台设备有证据。

### P2：真实使用后扩围

系统分享入口、长期稳定同步与备份/导出仍是 **M1 必须完成**，排在 P0 和 P1 的真实闭环之后验收，不得顺延成 M2。M1 首条真实闭环通过后，再依次推进共同相册与视频/语音、城市故事、纪念日/倒计时、时间胶囊、过去的今天及非 AI 周小结。M1 占位页不可当作已交付能力。

## 4. 协作防冲突规则

- 另一台机器只改 SDK、服务端、Room/同步及其测试；本机只改 Compose 页面、设计系统资源和视觉验收文档。`AppNavigation.kt`、`SyncSession.kt` 是交界文件，改动前先在本文件记录接口约定并由一方一次性接线，不在两台机器上同时改。
- 每个任务提交独立 commit；提交信息含任务号，报告改了什么、未验证什么、APK SHA。仓库分支推进不等于用户手机更新。
- 真机证据回填验收表后再勾执行计划；任何 UI 对照必须用**真实 Room 数据**。构建与设备测试留在 SDK 机器，本机不启动 Gradle/模拟器。

## 5. 当前待用户提供的现场材料

首页与编辑页截图或短录屏、安装 APK 的日期/版本，以及“点不开内容”的具体点击路径。收到后先确认是否与 `966f5b6` 的 UI 对应，再把复现定位为旧包、手势点击、Room 数据或详情渲染问题。材料未到之前，不把其中任何一种猜测写成根因。
