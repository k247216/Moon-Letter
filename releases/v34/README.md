# V34 · 现有功能耐用性与响应优化

不新增功能、不改手账风格，不清记录、相册、草稿或待上传内容，不换空间、不重新配对。沿用原签名覆盖安装，双方都更新。

## 本轮改动

- 时间轴日期和展示数据在后台准备，日期章节缓存，减少重复分组和滚动触发的页面重算；不截断旧记录。
- 记录小照片按列表尺寸解码，列表预览与详情图片分开缓存。详情、保存和导出的原件链路不变；照片墙比例、边框不改。
- 文字同步与昵称、头像、惊喜卡、胶囊、纪念日等辅助刷新分开；前台辅助任务一次只运行一个，退出前台取消，不阻塞下一轮文字同步。
- 资料和文字请求复用连接资源，但每次仍独立带上当前凭据；没有共享 HTTP 内容缓存。
- 相册同步无变更时只获取一次列表、只写入变化的行；有变更尝试（即使返回失败）仍再次确认服务端状态。保留本机原件、待发送封面选择与删除传播。
- 后端相册列表批量读取照片；8 个相册的实测查询次数从 10 降为 3（包含成员鉴权），返回格式不变。
- 昵称、头像和纪念日的迟到结果不能覆盖切换账号/空间后的缓存，包括 A→B→A；取消异常不再被吞掉。惊喜卡请求可及时取消。
- 头像后台暂存、原子替换；完整写盘不持有界面读取会话需要的锁，失败/取消保留原来的缓存。

## 验收重点

1. 连续滑动时间轴，进入详情再返回；小预览不影响打开大图或保存原件。
2. A 连续上传照片时，B 发文字/评论；A 不必退出重进才能收到。
3. 相册打开保持一段时间，再从对方新增或删除照片；仍应更新，不能因为减少重复工作而不获取新内容。
4. 断网写记录/添加照片，恢复网络、重启应用，核对待发送内容和双方删除结果。
5. 暂时隐藏记录、惊喜卡、胶囊到期展示和导出继续按上一版规则验收。

## 已知边界

自动测试不等于真实手机帧率或跨省延迟验收；目前未连接真机，也未替你执行服务器更新。相册仍使用全量元数据快照，海量照片增长时需要继续测量；相册两次数据库读取不是固定同一快照，并发变化可能短暂不一致，下轮同步恢复。
