# 月笺 V39 · 稳定阅读与独立纪念日

本轮代码修复、完整自动化回归与构建已完成，适合进入双机验收；不等于宣称真机长期稳定性已全部验证。阶段总结见同目录《阶段评估.md》。

## 本轮变化

- 启动不再把“本机数据还没读完”当成“没有记录”。第一帧等首批本机时间线和装饰图就绪，最多 1000ms，不等待公网；异常、初次连接、直达记录和编辑均有放行路径。
- 自选封面和头像改为后台限尺寸读取，不在主线程完整解码大照片。取消和切换来源后不发布旧结果；未知版本的图片提供方允许后台解码，但不冒用缓存签名。
- 已加载照片底色透明；阅读框按自然比例布局，同时尊重页面高度限制。照片墙、相册集和原件保存方式不变。
- 小列表预览、1200 阅读预览及最长边约 2048 的全屏显示分档；全屏仍下载原件，保存使用原件字节。显示清晰度与有限内存并存，不把全分辨率相机图片无限解码到内存。
- 记录、相册、装饰图复用 32MiB 保留像素缓存预算。可见图片、在途解码和其他应用内存额外计算。
- 修复照片失效后仍显示旧像素、挂载页面切换图片来源未更新、来源缓存交错等边界；原图暂时传输失败仍可保留已验证的预览。
- 纪念日单独设置：共同空间共享公历日期，本机设置提醒时间，未提交草稿与已确认配置分开。生日和心意卡仍保留独立入口，不复用其内容当纪念日。
- 默认草稿为 9 月 24 日，但原始年份必须明确选择，不猜今年。中秋农历规则本版延期，不固定成同一个公历日期。
- 纪念日确认需要服务端响应；旧 GET、并发写入、A→B→A、取消和写盘失败有保护。连接身份更新只替换其请求所有者，不重置阅读位置和记录草稿。
- 已确认提醒可以离线补排；关闭本机提醒、旧账号和过期日期不会错误通知；任务失败可重试，不把写盘失败冒充可靠投递。后台送达仍受系统权限及省电策略影响，不承诺精确分钟。
